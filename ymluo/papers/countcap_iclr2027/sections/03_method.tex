\section{\method}
\label{sec:method}

\subsection{Problem formulation}

Consider one decoder layer with $H_q$ query heads, $H_{kv}$ KV heads, head
dimension $d$, and history length $N$.
For query head $h$ mapped to KV head $g(h)$, dense attention is
\begin{equation}
 s_{h,i}=\frac{q_h^\top k_{g(h),i}}{\sqrt d},\qquad
 p_h=\softmax(s_h),\qquad
 o_h=\sum_{i=1}^{N}p_{h,i}v_{g(h),i}.
 \label{eq:full-attn}
\end{equation}
We seek a query-dependent set $\widehat S_h\subseteq[N]$ and compute
\cref{eq:full-attn} with exact Q/K/V after restricting and renormalizing
softmax to $\widehat S_h$.
Unlike eviction, every historical KV pair remains addressable and the set can
change at each decode step.

\subsection{Request-local QK-balanced coordinates}

\paragraph{Second moments.}
For every layer and KV head, \method samples post-RoPE prompt Keys at stride
32 and collects the final eight prompt Query positions from all GQA Query
heads mapped to that KV head.
It forms uncentered empirical second moments
\begin{equation}
 \widehat C_k=\frac{1}{m_k}\sum_{i=1}^{m_k}k_i k_i^\top,\qquad
 \widehat C_q=\frac{1}{m_q}\sum_{j=1}^{m_q}q_j q_j^\top .
 \label{eq:qk-moments}
\end{equation}
Because the Query sample is small, we first use fixed isotropic shrinkage
\begin{equation}
 S_q=(1-\lambda)\widehat C_q+
 \lambda\frac{\tr(\widehat C_q)}{d}I,\qquad \lambda=0.75.
 \label{eq:q-shrink}
\end{equation}
For a positive-semidefinite
$S=E\operatorname{diag}(\nu)E^\top$, define
$\mathcal F(S)=
E\operatorname{diag}(\max\{\nu_\ell,\epsilon_S\})E^\top$, where
$\epsilon_S=10^{-8}\max_\ell\nu_\ell+10^{-12}$.
The implementation sets
\begin{equation}
 C_k=\mathcal F(\widehat C_k),\qquad
 \widetilde C_q=\mathcal F(S_q)
 \label{eq:moment-floor}
\end{equation}
and uses these same floored eigenvalues in both square and inverse square
roots.  This consistent regularization is what preserves the exact
biorthogonal identity below.
No downstream label, task identity, or trained parameter enters the
estimates.

\paragraph{Biorthogonal factorization.}
Let the compact singular value decomposition be
\begin{equation}
 \widetilde C_q^{1/2}C_k^{1/2}=U\Sigma V^\top
 \label{eq:qk-svd}
\end{equation}
and define
\begin{equation}
 A=\widetilde C_q^{-1/2}U\Sigma^{1/2},\qquad
 D=C_k^{-1/2}V\Sigma^{1/2}.
 \label{eq:qk-factors}
\end{equation}
For column-vector Queries and Keys, $q'=A^\top q$ and $k'=D^\top k$.
When the regularized moments are positive definite,
\begin{equation}
 AD^\top=I,\qquad {q'}^\top k'=q^\top k,
 \label{eq:qk-exact}
\end{equation}
and
\begin{equation}
 A^\top\widetilde C_qA=D^\top C_kD=\Sigma.
 \label{eq:qk-covariance}
\end{equation}
Thus the coordinate transform is full rank and incurs no approximation.
The diagonal entries of $\Sigma$ order coordinates by joint Query--Key score
energy under the construction moments.

\subsection{Per-head mixed-bit rate allocation}

For $d=128$, \method partitions the transformed coordinates into eight
contiguous 16-D bands $\mathcal G_1,\ldots,\mathcal G_8$.
Each band receives $b_g\in\{0,1,2,4,8\}$ bits per coefficient.
An active band stores its codes and one FP16 scale per token, equivalent to
one metadata bit per coefficient for a 16-D band.
The physical rate is therefore
\begin{equation}
 R(b)=16\sum_{g=1}^{8}
 \left(b_g+\1[b_g>0]\right)\le240\ {\rm bits}.
 \label{eq:packed-rate}
\end{equation}
A zero-bit band has no code or scale.

Let $e_{i,g}(b)=k'_{i,g}-Q_b(k'_{i,g})$ be the Key reconstruction error for
band $g$, and let
\begin{equation}
 C'_{q,g}=\frac{1}{m_q}\sum_j q'_{j,g}{q'_{j,g}}^\top,\qquad
 C_{e,g}(b)=\frac{1}{m_k}\sum_i e_{i,g}(b)e_{i,g}(b)^\top .
\end{equation}
The allocator uses the exact Cartesian-sample band score distortion
\begin{equation}
 D_g(b)=\frac{1}{m_qm_k}\sum_{j,i}
 \left({q'_{j,g}}^\top e_{i,g}(b)\right)^2
 =\tr\!\left(C'_{q,g}C_{e,g}(b)\right)
 \label{eq:band-qmse}
\end{equation}
and solves
\begin{equation}
 b^\star=\arg\min_b\sum_{g=1}^{8}D_g(b_g)
 \quad\text{s.t.}\quad R(b)\le240.
 \label{eq:qmse-allocation}
\end{equation}
The implementation enumerates the small feasible set exactly and freezes one
allocation for each layer and KV head after prefill.
Equivalent dynamic programming has complexity
$O(G L R')$ for $G=8$ bands, $L=5$ levels, and normalized rate budget
$R'=15$.
The selected plain symmetric quantizers use max-absolute scaling for
2/4/8-bit bands, sign times mean absolute magnitude at 1 bit, and zero at
0 bits.
A fixed $(4,4,2,1,0,0,0,0)$ allocation is an equal-rate ablation.
  A deployment ablation instead uses
$D_g^{\rm K}(b)=\tr(C_{e,g}(b))$.
It removes Query weighting but retains QK-balanced coordinates.
The causal ablations in
\cref{tab:allocation-causal,tab:allocation-deploy} find matched quality and
lower optimized latency.  To keep the paper's quality and speed paths
identical, however, the frozen main method uses the query-weighted
\cref{eq:qmse-allocation}; Key-MSE remains an ablation.

The index stores 240 bits, or 30 bytes, per token and KV head.
FP16 K+V at $d=128$ stores $2\cdot128\cdot2=512$ bytes, so the index adds
$30/512=5.86\%$ to the exact KV footprint.
For GQA, mapped Query heads share $D$, the allocation, and the packed Key;
each Query head still computes its own transformed Query, proxy scores, and
candidate set.

\subsection{Packed retrieval and exact sparse attention}

At decode step $t$, \method transforms and INT8-quantizes the current Query.
A fused CUDA kernel scans every packed Key band and accumulates approximate
scores.
The reference path applies exact top-$B(N)$ to these approximate scores,
where $B(N)$ is given by \cref{eq:budget-intro}.
This is a linear scan over 30-byte index entries rather than full FP16 Keys.
It does not score any token with exact QK before selection.

Selected positions $\widehat S_h$ gather their original GPU-resident FP16
Keys and Values and compute
\begin{equation}
 \widetilde p_{h,i}=
 \frac{\exp(s_{h,i})}{\sum_{j\in\widehat S_h}\exp(s_{h,j})},
 \qquad
 \widetilde o_h=\sum_{i\in\widehat S_h}
 \widetilde p_{h,i}v_{g(h),i}.
 \label{eq:sparse-attn}
\end{equation}
The final score and Value arithmetic are exact; approximation affects only
the discrete selected set.
There is no exact rerank, router, task rule, sink/recent reservation, or Full
fallback.

\subsection{Robust current-Query Value-tail residual}

Selected-only attention can fail even under an accurate Key ranking when the
omitted set contains many small but coherent Value contributions.  Let
$S=\widehat S_h$, $T=[N]\setminus S$, and let $\widehat\tau$ be the proxy-score
threshold.  During the packed-Key scan, the Robust profile also accumulates
\begin{equation}
 \widehat Z_T=\sum_{i\in T}e^{\widehat s_i-\widehat\tau},\qquad
 \widehat c_T=\sum_{i\in T}e^{\widehat s_i-\widehat\tau}\widehat c_i.
 \label{eq:value-tail-statistics}
\end{equation}
For each layer and KV head, a request-local PCA of uniformly stratified
Values gives a mean $\mu_v$, a rank-16 basis $P_v$, and coefficients
$c_i=P_v^\top(v_i-\mu_v)$.  Coefficients are stored as block-affine INT4 with
256-token blocks.  The Value code costs 64 bits per token; FP16 minima and
scales add two amortized bits, so Key plus Value indices use
$(240+66)/4096=7.47\%$ of FP16 K+V.  The mean and basis are constant per
request/layer/head and are reported separately from this per-token rate.

The consumer computes the exact selected numerator $u_S$, denominator $Z_S$,
and selected maximum $m$ from original K/V.  It then returns
\begin{equation}
 \widehat o_\alpha=
 \frac{u_S+\alpha e^{\widehat\tau-m}
   (\widehat Z_T\mu_v+P_v\widehat c_T)}
 {Z_S+\alpha e^{\widehat\tau-m}\widehat Z_T},
 \qquad \alpha=0.5.
 \label{eq:robust-tail-output}
\end{equation}
The common anchor makes the mixed exact/proxy computation numerically stable.
The fixed shrinkage suppresses noisy tail estimates while retaining coherent
aggregate Value.  It was selected on a preregistered weak-case set and then
frozen for held-out seeds; it is not a learned router.  QKSieve-Fast omits
\cref{eq:value-tail-statistics,eq:robust-tail-output}; QKSieve-Robust uses
them without changing $B(N)$ or reading additional exact K/V.

\subsection{Registered execution profiles}

\paragraph{Reference profile.}
The quality reference constructs $(A,D)$ and the query-weighted
\cref{eq:qmse-allocation} solution from the current prompt, materializes all
packed-index proxy scores, and applies deterministic top-$B(N)$.  This
isolates the representational approximation from threshold estimation and is
the profile used by the complete Llama LongBench result.

\paragraph{Deployment profile.}
The optimized profile uses the same request-local $(A,D)$ and query-weighted
allocation as the reference, but replaces complete score materialization and
top-$k$ with a sampled threshold.  Let $r(N)=B(N)/N$ be the active rate.  The
frozen sample count is
\begin{equation}
 m(N)=\min\{N,512,\max(256,\lceil16/r(N)\rceil)\}.
 \label{eq:frozen-quantile-samples}
\end{equation}
Before the 512-sample cap activates, this rule targets approximately 16
entries from the selected tail.  The cap bounds threshold-estimation cost at
long lengths; its quality is therefore audited empirically rather than
claimed from the sampling heuristic alone.  The kernel evaluates $m(N)$
regularly stratified index entries, estimates the target score quantile, and
scans the packed index once while writing entries above the threshold
directly to a bounded candidate buffer.
It therefore materializes neither an $N$-length score tensor nor a generic
top-$k$ workspace.  The realized count can fluctuate around $B(N)$; the
exact sparse-attention consumer is otherwise unchanged.

\paragraph{Robust profile.}
The Robust consumer uses the same deployment Key index, sampled threshold,
and candidates, but fuses \cref{eq:value-tail-statistics} into the scan and
uses the exact-selected-plus-tail kernel in \cref{eq:robust-tail-output}.
It is therefore a consumer-side robustness profile, not a different selector.

\paragraph{Frozen main profile.}
The paper's main method is the Robust consumer at every evaluated length,
with $r_v=16$ and $\alpha=.5$.  We deliberately do not switch to Fast at a
hand-set context length: such a boundary is not implied by the error identity
and would make the method definition depend on an empirical patch.  Fast is
retained only as a selected-only ablation that isolates the cost and quality
contribution of omitted-Value estimation.

The reference, Fast, and Robust profiles share the request-local QK-balanced
representation, query-weighted allocation, budget schedule, exact FP16 K/V,
and absence of reranking or fallback.  They differ in candidate selection and
whether the omitted Value tail is estimated.  We identify the producing profile for every result
rather than combining their quality and speed measurements as a same-path
claim.

\subsection{Index construction and update}

Dense chunked prefill constructs the ordinary exact KV cache.
After the prompt-tail Queries are available, both reference and optimized
profiles compute request-local $(A,D)$ and $b^\star$ for each layer and KV
head.  They project historical Keys in chunks and write the packed index directly.
For each generated token it appends the new exact K/V and projects and packs
one new Key entry.
The transforms and bit allocations remain frozen throughout generation.
An optional memory-offload extension can place exact KV in pinned host memory,
but it is not used by the main GPU-resident quality and speed claims.

\paragraph{Implementation and accounting.}
The reference path applies the Query transform and then invokes a CUDA kernel
for bandwise INT8 quantization; a separate CUDA kernel scans the packed
variable-bit index.
For the GQA-4 architecture shared by the three target models, we additionally
fuse the $128\times128$ Query projection and bandwise INT8 quantization into
one CUDA kernel that reuses each KV-head basis across its four mapped Query
heads.
The deployment scan likewise uses a warp-level sampled quantile and
dispatches compile-time specializations for the small set of observed bit
patterns.  For GQA-4 it reads each packed KV-head index once for the four
mapped Query heads.  The frozen native-MHA implementation instead uses one
KV head per Query head, without replicating K/V, and fixes the exact sparse
attention reduction to eight splits.  Increasing this split count is not a
valid speed knob: although split 16 is faster in isolation, it fails the
output-equivalence check at long lengths.
Its FP32 accumulation is rounded to the model dtype before INT8 quantization,
matching the numerical boundary of the reference path.
Across FP16 and BF16 validation at 4K and 32K, the fused path matches Query
codes, proxy scores, selected sets, and exact sparse-attention outputs within
the registered tolerances.
The MHA implementation supports both Fast and Robust.  Their directly timed
attention calls contain Query projection/quantization, sampled scan, candidate
compaction, and exact sparse attention; Robust additionally accumulates and
consumes the rank-16 INT4 Value tail.  We also time both paths inside a real
MHA model.  The GQA fusion is not promoted as a generic GQA-8 optimization: complete
selection is slower at 32K in that configuration.
We report architecture-specific paths explicitly and keep downstream
quality tables tied to the method identifier that actually produced them.
Top-$k$, exact-KV gather, sparse attention, and per-token index append are
measured separately.
Whole-model decode timing synchronizes the GPU and includes Query transform
and quantization, packed scan, candidate selection, gather, exact sparse
QK--softmax--AV, cache update, and all non-attention model work.
Prefill and index construction are reported separately and are included in
request-level break-even analysis.
