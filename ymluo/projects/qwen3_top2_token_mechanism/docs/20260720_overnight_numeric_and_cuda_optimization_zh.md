# 数值机制与长序列 CUDA 优化结果

更新时间：2026-07-20

## 1. 结论

本轮没有训练新 router，也没有针对主题调预算。当前最好的实用版本是：

```text
PCA64 + 分频带 INT4 的 K 索引
-> 每个 query head 扫描全历史并取 8% 候选
-> 用原始 K 精确重排
-> 每个 query head 保留精确 top-2%
-> 根据 GPU SM 数和工作量自动选择 CUDA split，并行聚合原始 V
```

自动 split 只改变 CUDA 如何并行完成最后一步，不改变候选、top-2% token、attention score 或预算。因此它与原 PCA64 方法的算法质量等价，不需要训练，也不依赖任务类型。在 RTX 3090 上，64K 自动保持原 kernel，128K 自动选择 split-16。

当前最重要的新结果：

| 指标 | 原 PCA64 | 当前 128K 版本 |
|---|---:|---:|
| 128K attention 完整流水线 | 1.156 ms | **0.879 ms** |
| 相对 Full SDPA | 2.11x | **2.78x** |
| 128K steady model forward | 121.8 ms/token | **110.9 ms/token** |
| 相对匹配 Full forward | 2.32x | **2.55x** |
| 16-token 整模型在线速度，Medicine | 1.74x | **1.84x** |
| 16-token 整模型在线速度，Politics | 1.72x | **1.84x** |
| 1024-token 整模型在线速度，四主题 | -- | **2.4996x** |

这已经把“128K 长生成约 2.5x”做成了整模型实测结果，而不是 attention 理论外推。短短 16 个 decode token 的端到端结果仍只有约 1.84x，主要因为首步建立 PCA basis 和量化索引的固定成本还没有充分摊销。

## 2. 为什么原实现没有兑现更高速度

对 128K 紧凑流水线逐阶段 profile 后，主要耗时如下：

| 阶段 | 每层耗时 | 占比 |
|---|---:|---:|
| 最终 top-2% V attention | 0.441 ms | 35.93% |
| PCA64 INT4 全局扫描 | 0.268 ms | 21.79% |
| 两次 top-k | 0.262 ms | 21.36% |
| 8% 候选 exact QK | 0.141 ms | 11.52% |

原来的最终 attention 为每个 query head 只启动一个 CUDA block。Qwen3-4B 共有 32 个 query head，因此一次只启动 32 个 block；RTX 3090 有 82 个 SM，GPU 连一半都占不满。虽然只读取 2% KV，但 kernel 并行度太低，带宽和计算单元均没有充分使用。

## 3. Split-parallel sparse attention

### 3.1 算法

对每个 query head 已经选出的 top-2% token，按 token 维切成 16 份：

```text
每个 head 的 top-2% token
    -> 16 个 CUDA block 分别计算局部 softmax 分子
    -> 写入 FP32 partial output
    -> 一个很小的 reduction kernel 求和
```

softmax 最大值和归一化分母仍由原来的精确 score 得到。拆分只应用在线性可加的 value 加权和上，所以没有近似算法变化。FP16 输出相对旧 kernel 的最大绝对误差不超过 `3.05e-5`。

### 3.2 单独 value attention

| 上下文长度 | 原 kernel | Split-8 | Split-16 | 最佳加速 |
|---:|---:|---:|---:|---:|
| 32K | 0.095 ms | **0.032 ms** | -- | 2.97x |
| 64K | 0.238 ms | **0.070 ms** | -- | 3.40x |
| 128K | 0.466 ms | 0.119 ms | **0.071 ms** | **6.55x** |

### 3.3 包含所有检索开销的 attention 流水线

| 上下文长度 | Full SDPA | 原 PCA64 | Auto-split | 最佳实用选择 |
|---:|---:|---:|---:|---|
| 32K | 0.629 ms | 0.818 ms | 自动不拆分 | Full |
| 64K | 1.249 ms | 0.839 ms | **0.809 ms** | 自动不拆分，1.55x |
| 128K | 2.443 ms | 1.156 ms | **0.879 ms** | 自动 split-16，**2.78x** |

32K/64K 时 split kernel 节省的 value attention 时间小于额外 partial buffer 和 reduction 开销，不能无条件开启。当前实现根据 GPU 的 SM 数、query head 数和每个 split 的 token 数自动决定；在 RTX 3090 上，64K 不拆分，128K 选择 split-16。32K 整条稀疏流水线仍慢于 Full，因此系统层还需要一个 Full/sparse 长度 gate。

## 4. 128K 整模型配对验证

设置：Qwen3-4B-Instruct、2 张 RTX 3090 分层放置、batch 1、128K history；Full 和 sparse 使用完全相同的文本与目标 token。表中的“在线时间”从 prefill 结束后开始统计，不包含 prompt prefill，但包含 sparse 首个 token 的 PCA basis、索引构建以及后续全部模型计算和检索开销。

### 4.1 每主题 1024 个逐 token 预测

| 主题 | Full PPL | Auto-split PPL | Full 在线时间 | Auto-split 在线时间 | 加速 |
|---|---:|---:|---:|---:|---:|
| Medicine | 9.9795 | **9.9179** | 571.896 s | 228.706 s | **2.5006x** |
| Politics | 12.3210 | **12.1639** | 571.856 s | 228.687 s | **2.5006x** |
| Computer | 7.4658 | **7.4049** | 572.136 s | 229.003 s | **2.4984x** |
| Space | 12.8824 | **12.8819** | 572.462 s | 229.078 s | **2.4990x** |
| **四主题合计/平均** | NLL 2.34451 | **NLL 2.33769** | **2288.350 s** | **915.473 s** | **2.4996x** |

四主题共 4096 个目标 token，几何平均 PPL 从 `10.4281` 变为 `10.3573`，质量保持率为 `100.68%`。四个主题均未出现 PPL 恶化，且每个主题的整模型在线速度都约为 2.50x。这是当前最有代表性的 128K 质量与实际速度结果。

### 4.2 每主题 64 个逐 token 预测

| 主题 | Full PPL | Auto-split PPL | Full 在线时间 | Auto-split 在线时间 | 加速 |
|---|---:|---:|---:|---:|---:|
| Medicine | 18.3923 | **17.7338** | 35.673 s | 15.382 s | **2.32x** |
| Politics | 9.3661 | **9.1145** | 35.682 s | 15.353 s | **2.32x** |
| Computer | **10.0714** | 10.2632 | 35.663 s | 15.416 s | **2.31x** |
| Space | 9.7655 | **9.3660** | 35.675 s | 15.391 s | **2.32x** |

四主题共 256 个目标 token，几何平均 PPL 从 `11.4089` 变为 `11.1646`。这组结果不支持“稀疏方法必然提高质量”的结论，但说明当前 2% attention 没有出现系统性 PPL 损失。相比 16-token 设置，固定索引成本得到更多摊销，端到端加速从 1.86x 提升到 2.32x。

其中 `computer / space / religion` 是本轮新增的独立主题。三者平均 NLL 从 `1.90163` 变为 `1.90982`，几何平均 PPL 质量保持率为 **99.18%**，在线速度约为 **1.87x**。五主题合计 NLL 略优于 Full，但每个主题只有 16 个目标 token，不能把这组小样本波动宣称为普遍质量提升；合理结论是没有观察到系统性质量损失。

## 5. 从并行研究迁移的数值机制

并行任务给出的两个有用观察是：

1. RoPE 会让长距离 token 的内容相似性和真实 post-RoPE QK 排名发生偏离；
2. 被 top-2% 丢弃的大量小 logit 虽然单个不重要，但会共同影响 softmax 分母和值向量期望。

本轮把这两个观察都实现并做了验证。

### 5.1 低频 inverse-RoPE 救援

增加一个 32 维最低频、INT2 的 inverse-RoPE K 索引，每四步扫描一次并补充 0.5% 候选。它使 Sports/Medicine 的 top-2% recall 从 `98.653%/97.984%` 提高到 `98.859%/98.301%`，但 64K PPL 没有稳定优于基础 PCA64，并增加约 0.09 ms/layer/token。因此保留为论文机制消融，不作为默认路径。

### 5.2 0.5% 尾部采样校正

从未选 token 中均匀采样 0.5%，估计遗漏的 softmax 分母和 value 一阶矩，再与精确 top-2% 输出合并。为了避免高方差，另外实现了偶数/奇数子样本一致性 shrink 和一个无需训练的 selected-mass gate。

在真实 QK trace 上，输出相对 L2 误差有明确改善：

| 方法 | Sports | Medicine |
|---|---:|---:|
| 仅 PCA64 top-2% | 22.83% | 28.53% |
| 原始尾部校正 | 18.57% | 24.25% |
| 50% shrink | **14.97%** | **19.33%** |

但它在 64K 六主题 PPL 上没有稳定超过基础方法，且实际 attention 读取从 2% 增至 2.5%。质量收益和时间收益不同时成立，因此不进入当前主版本。selected-mass gate 在 32K 六主题上得到最优平均 NLL `2.78594`，优于 Full 的 `2.79061`，可作为质量消融报告。

## 6. 当前应冻结的版本

```text
索引：post-RoPE PCA64，四组 16 维 spectral scale，INT4
索引大小：36 B / token / KV head
近似候选：每个 query head 8%
精确重排：原始 K
最终预算：每个 query head 2%
最终 attention：硬件感知 auto-split；当前 64K 不拆分、128K split-16
训练/任务标签/oracle：均不需要
```

索引相对 FP16 K+V 的理论大小为：

```text
36 / (2 * 128 * 2) = 7.03125%
```

这个 `7.03%` 只表示紧凑 K 检索索引。当前 PPL harness 为了验证算法质量，仍把原始完整 K/V 留在 GPU 上；它不能被表述为“完整系统 GPU KV 只有 7%”。论文中的真实显存结论仍需把此检索器接入已实现的 CPU/offload + GPU hot-cache 物理路径后重新测量。

单主题 128K Auto-split/Full 成对复现实验脚本为：

```text
scripts/run_autosplit_128k_pair_20260720.sh GPU_LIST TOPIC [EVAL_TOKENS]
```

## 7. 下一步只做高价值工作

1. 把 split-16 接到物理 offload/hot-cache 路径，测真实 GPU 峰值显存、PCIe 读取和长生成端到端速度。
2. 把一次性 PCA basis 与索引构建移入 prefill 流水线并并行化；这是短生成从 1.84x 接近 steady 2.55x 的关键。
3. 在 H100 上重新调 split 数；3090 的 `16` 不能直接假定为 H100 最优。
4. 扩展到 LongBench、RULER 和长生成任务，保持冻结的 8%/2% 参数，不再按任务调参。

本轮不建议继续调尾部采样率、低频维数或 gate 阈值。它们已经说明机制成立，但没有形成跨长度的质量与速度联合增益。
