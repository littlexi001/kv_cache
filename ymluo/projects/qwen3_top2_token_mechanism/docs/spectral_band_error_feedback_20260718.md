# 协方差加权频带误差反馈检索

## 1. 研究问题

当前 PCA64+INT4 索引能够以较低存储成本估计每个 KV head 的 QK 分数，但每个 decode 步仍要扫描全部 64 个 PCA 维度。直接减少到固定 16 维虽然更快，却会永久丢弃其余维度的 query 变化，连续生成时误差会累积。

因此这里研究的问题不是选择某个更好的 top-k 或阈值，而是：**每步只允许读取一个连续 16 维频带时，如何让 64 维 QK 分数随 query 变化持续更新，并避免未传输信息永久丢失。**

## 2. 新观察

连续 decode 的 PCA query 变化具有两个性质：

1. 相邻 token 的 query 变化较小，但变化能量并不固定集中在同一个 PCA 频带。
2. 当前步没有传输的频带变化在后续仍然有价值，直接截断会丢失它，而保留残差后可以在未来补偿。

这与压缩通信中的 error feedback 类似，但这里反馈的对象不是梯度，而是每个 layer、KV head 的近似 QK score 状态。

## 3. 方法

将 PCA64 划分为 4 个连续 16 维频带。每个 layer、KV head 维护：

- query 锚点 `a`；
- 历史 token 的近似 score cache；
- PCA 维度对应的 key 协方差特征值 `lambda`。

在第 `t` 个 decode 步：

1. 计算尚未传输的 query 残差 `r = q_t - a`。
2. 对每个 16 维频带计算协方差加权残差能量，并在同一 KV head 的 GQA query heads 间求和：`E_b = sum(lambda_d * r_d^2)`。
3. 选择能量最大的频带 `b* = argmax E_b`。
4. 只扫描该频带的 INT4 key，增量更新 score cache：`S <- S + K_b* r_b*`。
5. 只把锚点的该频带更新为当前 query；其余频带残差保留，后续仍可被选择和补偿。

该策略每步、每个 KV head 只读取 16 个连续 PCA 维度。与固定 16 维不同，它不会永久丢弃其余 48 维；与 spectral-top2 不同，它不需要让部分 heads 周期性扫描完整 PCA64。

在 key 协方差近似为频带块对角时，选择最大 `E_b` 等价于在“一步只能传一个频带”的约束下，贪心最小化更新后的期望 score 均方误差。

## 4. 当前结果

### 4.1 真实 QKV trace，Llama，32K

每个主题使用 5 层、连续 16 个 decode 步。候选池为 top-8%。

| 数据 | 完整 PCA64 候选召回 | BandEF 候选召回 | Round-robin 召回 | 稀疏输出 cosine | 稀疏输出相对 L2 |
|---|---:|---:|---:|---:|---:|
| 体育 | 99.11% | 94.21% | 92.60% | 0.99938 | 1.296% |
| 医学 | 98.55% | 92.03% | 89.41% | 0.99833 | 2.478% |

BandEF 的候选召回低于每步扫描完整 PCA64，但稳定优于同计算量的轮询频带；最终 attention 输出误差明显小于候选集合误差，说明丢失的候选大多不是高 attention-mass token。

### 4.2 Qwen3-4B，8K targeted PPL

| 数据 | Spectral-top2 PPL | BandEF PPL | PPL 变化 | Spectral-top2 links | BandEF links | links 降幅 |
|---|---:|---:|---:|---:|---:|---:|
| 体育 | 13.8183 | 14.2732 | +3.29% | 3.011% | 2.058% | 31.64% |
| 医学 | 6.0356 | 6.1859 | +2.49% | 2.606% | 1.912% | 26.63% |

BandEF 用约 2.5% 至 3.3% 的 PPL 增加换取约 27% 至 32% 的实际 attention links 降低。表中 BandEF 是 CUDA 融合实现；该结果仅覆盖两个 targeted 主题和 32 个评测 token，还不能替代完整 held-out PPL 与 LongBench 实验。

### 4.3 CUDA 融合内核

数值审计使用连续 16 个随机游走 query 步，对比 CUDA 与逐步 FP32/PyTorch 参考算法。

| 序列长度 | 频带选择一致率 | top-2% 候选重合率 | score 相对 L2 | 相对 spectral-top2 检索速度 |
|---:|---:|---:|---:|---:|
| 32K | 100% | 99.92% | 0.066% | 2.23x |
| 64K | 100%（单步） | 待补 | 0.021%（单步） | 3.12x |
| 128K | 100%（单步） | 待补 | 0.021%（单步） | 2.39x |

这些是检索 score 更新子系统的速度，不是完整 model forward 或整段 decode 加速。服务器 GPU 当前有并发任务，因此暂不报告端到端绝对时间。

### 4.4 从数值误差得到的 Expected-Crossing BandEF

进一步诊断发现：

- 协方差预测的剩余 score 标准差与真实误差标准差高度一致，二者平均比值在体育/医学上分别为 1.025/1.021。
- `剩余误差标准差 / top-2% 到候选池的分数缓冲` 对候选危险状态的 AUC 为 0.967/0.981。
- BandEF16 在完整 PCA64 已成功召回后仍漏掉 78,476/105,427 个目标位置，而 PCA64 自身只漏 13,648/22,295 个位置。因此主要问题是延迟更新误差，不是 PCA64 表征能力不足。

基于这些数值，设计 Expected-Crossing BandEF（EC-BandEF），不训练 router：

1. 用剩余协方差能量直接估计未更新 score 的标准差 `sigma`。
2. 把候选池外 token 穿过当前近似 top-2% 分数线的概率写成高斯尾概率。
3. 对候选池外 token 的概率求和，得到期望漏项数。
4. 若期望漏项数仍大于 `5% * top-2% token 数`，继续补算下一高残差能量频带；否则停止。5% 直接来自 95% 召回目标，不从测试集搜索。

| 数据 | BandEF16 召回 | EC-BandEF 召回 | 完整 PCA64 召回 | EC-BandEF 输出 L2 | 平均扫描维度 | 扫满 64 维比例 |
|---|---:|---:|---:|---:|---:|---:|
| 体育 | 94.21% | 98.58% | 99.11% | 0.31% | 36.72/64 | 9.17% |
| 医学 | 92.03% | 97.96% | 98.55% | 0.67% | 37.63/64 | 10.33% |

EC-BandEF 相对完整 PCA64 减少约 41% 至 43% 的索引维度扫描，同时保留约 99.4% 的 PCA64 候选召回。当前结果是 32K 真实 QKV trace 离线实验；真实 PPL 与融合内核尚待接入。

## 5. 已排除的结构方案

以下结论来自机制对照，不作为主方法贡献：

- 随机采样 seed 扩张候选：不如确定性补充下一高分候选。
- 按 PCA-K 相似度静态重排物理 KV：32K page 数在体育/医学反而增加 16% 至 30%，说明 key 相似不等于 query 共访问。
- GQA query-ball 严格包络：为了保证相同候选，需要扫描约 98% token，失去加速价值。
- 残差范数证书：频带 Cauchy 上界约为 score 标准差的 2.07 至 2.32 倍，严格证书需要保留 86.62% 至 90.02% token；在固定 8% 候选池下，体育/医学召回反而降到 91.15%/87.15%。上界丢失方向与符号，过松，不再调系数。
- Query 共访问图物理打包：1K 可减少约 12% 至 15% page，但 4K 下降到约 5% 至 7%，只适合作为系统辅助优化，不足以成为主创新。

## 6. 下一步验证

1. GPU 空闲后复验 Qwen3-4B 融合内核的 PPL 与端到端速度。
2. 在不调方法阈值的前提下，扩大到多个主题、多个窗口和 held-out 文本。
3. 接入 LongBench/RULER，比较完整 PCA64、spectral-top2、固定频带、round-robin 和 BandEF 的质量-速度 Pareto。
4. 推导协方差块对角假设下的单步最优性，以及累计残差有界条件。
