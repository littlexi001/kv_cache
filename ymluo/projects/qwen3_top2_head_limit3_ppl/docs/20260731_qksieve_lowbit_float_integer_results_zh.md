# QKSieve 低比特浮点与整数索引实验

## 结论

当前可以直接部署的默认候选是 **128-bit 整数索引（band 位宽
`[4, 2, 0, 0, 0, 0, 0, 0]`）**：

- 32K、8 个主题、256 个独立 PPL token 上，质量保持率为
  **99.992%**，topic-cluster bootstrap 95% 区间为
  **[97.87%, 102.35%]**。
- 索引占完整 FP16 K/V 的 **3.125%**。
- 32K 实际模型稳态速度为 **1.515x**，高于 160-bit 的
  1.479x 和 192-bit 的 1.470x。
- 相对当前约 236-bit 自动整数索引，候选一致的 plain scan kernel
  在 32K 和 128K 分别快 **1.243x** 和 **1.211x**。

低比特浮点在 96/128-bit 区间的离线召回略优于同码率整数，但真实
模型 PPL 反而略差。128-bit minifloat 相对 128-bit 整数的配对质量比
为 **99.799%**，95% 区间为 **[99.593%, 99.995%]**。因此离线
attention-mass 收益没有转化为输出收益，不建议为它实现新的融合
CUDA 解码器。

## 实验问题

QKSieve 当前把每个 128 维 head 划分成 8 个 16 维 band，并为每个
激活 band 保存一份 FP16 scale。这里比较两个问题：

1. 非均匀低比特浮点码本能否在更低位宽下保留更多 top-k 证据？
2. 只使用硬件友好的 1/2/4-bit 整数，能否把当前约 240-bit 索引继续
   压缩到 192/160/128-bit，而不损失实际模型质量？

物理开销按下式统计，包含 scale，不使用“只算 payload”的理想化口径：

```text
bits_per_token_head = sum_b(16 * bit_b + 16 * I[bit_b > 0])
index_ratio = bits_per_token_head / (2 * 128 * 16)
```

分母是完整 FP16 K 和 V 的 4096 bit。

## 量化格式

整数使用对称码本：

- 1-bit：`{-1, +1}`；
- 2/4/8-bit：对称整数码本；
- max-abs scale 保护极值；
- 另测了迭代最小 MSE scale，以及实验性的 3-bit 整数。

低比特浮点使用非均匀码本：

- 2-bit：`{-1, 0, +1}`；
- 3-bit：E2M0 风格的对数级别；
- 4-bit：归一化 E2M1 风格级别；
- 8-bit：E4M3 风格级别；
- 同时比较 max-abs scale 和迭代最小 MSE scale。

位宽由每个 layer/head/band 的 QK 加权误差动态规划分配。发现阶段使用
真实 Q/K held-out trace，覆盖：

- Qwen3-4B：体育、医学，32K 与 96K；
- Llama-3.1-8B：体育、医学，32K；
- Qwen2.5-7B：体育、医学，32K。

校准 query 和评测 query 严格分开，共 8 条 trace。

## 离线召回结果

下表是 8 条 held-out trace 的加权平均。`Mass@r` 表示按近似分数选择
历史 token 后，保留的真实 attention mass；数字越大越好。

| 格式 | 物理 bit/head/token | 选 2% Mass | 选 4% Mass | 选 6% Mass |
|---|---:|---:|---:|---:|
| 整数 max-abs，约 240-bit | 236.16 | 83.62% | 88.31% | 90.88% |
| 整数 max-abs，192-bit | 191.45 | 83.31% | 88.08% | 90.70% |
| 整数 max-abs，160-bit | 158.06 | 82.54% | 87.46% | 90.18% |
| 整数 max-abs，128-bit | 124.54 | 80.80% | 85.90% | 88.81% |
| 浮点 max-abs，128-bit | 124.57 | **81.39%** | **86.45%** | **89.31%** |
| 整数 max-abs，约 96-bit | 80.00 | 78.95% | 84.31% | 87.38% |
| 浮点 max-abs，约 96-bit | 84.12 | **79.78%** | **85.07%** | **88.10%** |

在几乎相同的 128-bit 物理成本下，浮点相对整数提高：

- 2% 选择预算：attention mass **+0.59 个百分点**；
- 4% 选择预算：**+0.54 个百分点**；
- 6% 选择预算：**+0.49 个百分点**。

因此“低比特浮点在极低码率更有效”得到支持，但增益约半个百分点，
不是数量级变化。到 160-bit 以上后优势基本消失，因为 QK-balanced
变换和 per-band scale 已经消除了大部分动态范围问题。

最小 MSE scale 并不总是优于 max-abs。它优化平均重构误差，却可能牺牲
决定 top-k crossing 的少数极值；因此检索索引更适合 max-abs 或直接
优化排序边界，而不是只优化普通 MSE。

## 真实 PPL 与模型速度

使用 Qwen3-4B、32K 历史、每个 head 最多精确消费 1280 个 token。
8 个主题分别独立运行，每个主题评测 32 个 token。

| 配置 | PPL | 相对 Full 质量 | 95% CI（按主题） | Top-1 一致率 | 索引/完整 KV | 稳态 ms/token | 稳态加速 |
|---|---:|---:|---:|---:|---:|---:|---:|
| Full FP16 KV | 5.4560 | 100.000% | - | 100.00% | 0% | 89.30 | 1.000x |
| 整数 192-bit `[4,4,1]` | 5.4785 | 99.589% | 97.72%–101.46% | 97.66% | 4.688% | 60.74 | 1.470x |
| 整数 160-bit `[4,4]` | 5.4665 | 99.807% | 97.86%–101.98% | 97.66% | 3.906% | 60.39 | 1.479x |
| 整数 128-bit `[4,2]` | 5.4564 | **99.992%** | 97.87%–102.35% | 97.66% | **3.125%** | **58.94** | **1.515x** |
| minifloat 128-bit `[4,2]`，质量参考 | 5.4674 | 99.791% | 97.61%–102.26% | 97.66% | 3.125% | 不作部署比较 | 不作部署比较 |

三种稀疏配置的置信区间高度重叠。128-bit 的点估计最好不能解释为
它在总体上必然比 160/192-bit 更准；可靠结论是当前样本没有检测到
128-bit 退化，同时它的显存和速度最优。

minifloat 与整数 128-bit 使用完全相同的主题和 token。直接配对后，
minifloat 的平均 NLL 高 0.002013，质量比为 99.799%，8 个主题中只有
2 个更好。其质量参考路径保存反量化浮点代理 K 并使用浮点矩阵乘法，
只验证数值质量，不代表未来 LUT kernel 的速度。

固定索引建立开销约 2.23 秒。上表使用 steady decode，不把一次性索引
建立时间摊进 32 个评测 token；在线总延迟必须根据实际生成长度另行
计算 break-even。

## Kernel 结果与正确性审计

以下只采用候选输出已核对的 plain scan kernel：

| 长度 | 160-bit 相对约 236-bit | 128-bit 相对约 236-bit |
|---:|---:|---:|
| 8K | 0.963x | 0.987x |
| 16K | 0.958x | 0.978x |
| 32K | 1.201x | **1.243x** |
| 64K | 1.060x | **1.116x** |
| 128K | 1.094x | **1.211x** |

短序列下 kernel launch 和固定控制流占主导，减小位宽没有收益；32K
之后才逐步转为内存带宽收益。

审计同时发现：当前 band-major kernel 在含 1-bit band 的约 236-bit
和 192-bit 配置上，与 plain reference 存在 `1e-6`–`6e-5` 量级的
阈值漂移，严格候选集合不一致；扩大输出容量、排除 overflow 后差异
仍存在。这更像浮点累加顺序造成的 top-k 边界差异，而不是明显的解码
错误，但在完成排序等价性分析前，这些 band-major 时间不能作为严格
等价的论文数字。160/128-bit 配置不含 1-bit band，阈值和候选均完全
一致。主报告保守采用 plain kernel。

## 当前判断

1. **部署主配置**：先使用整数 128-bit `[4,2]`。它无需新量化格式，
   已通过真实 PPL，并给出最好的当前速度/索引 Pareto 点。
2. **不实现浮点部署 kernel**：minifloat 的离线 mass 小幅提升没有
   转化为 PPL，配对结果还略差于整数；继续开发 LUT kernel 的预期
   收益不足。
3. **不推荐**：单纯用 LSQ/MSE scale 继续压位宽。top-k 检索关心排序
   crossing，平均重构误差不是正确目标。
4. **仍需扩大验证**：当前实际 PPL 只有 8 个主题、256 token。冻结
   128-bit 配置后，需要在未参与选择的模型、长度和任务上验证，避免
   把小样本噪声写成确定性提升。
